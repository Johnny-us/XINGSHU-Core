# 主动协作 v0.1.0：范围与使用条件

本软件组件的已验收路线是：**Codex 主持发送明确授权的任务原文 → 现有 Web GPT 对话独立复核 → Codex 在原入口读取实际模型结果。** 这是需要智能端在当前调用中主持的前台能力。

安装代码不提供账户权限。新机器需要 Python 3.11+、macOS/Linux、已登录且实际提供官方聊天读取/发送工具的客户端，以及所有者选择的两端绑定。首次使用步骤见 [安装说明](COLLABORATION_INSTALL.md)。Windows 尚未支持。

## 发布内容

- 通用连接库、精确原文投递检查、去重与不确定状态停止。
- 项目路由、交接包及换窗接续契约，作为开发接口。
- `xingshu-collab` 命令、当前调用内的官方工具桥，以及明确调用的 `xingshu-collaborate` 技能。
- 独立本机配置、工具与真实端点检查、可恢复技能归档。

组件版号为 `0.1.0`，软件标签为 `collaboration-v0.1.0`。它随 `xingshu-core 0.4.0.dev0` 分发，作为初始预发布；这不是整个 Core 的稳定版，也不是治理生效标签。

## 验收依据与限制

| 检查 | 已取得的证据 | 限制 |
|---|---|---|
| 源码与公私边界 | 精确源码与打包文件独立读取、摘要及模块对应关系复核 | 原始账户与聊天证据留在私人层 |
| Python / JavaScript | 本地全仓 1108 项测试及 954 子测试通过；独立组件复跑 288 项及 5 子测试、JavaScript 19 项通过 | 合成测试不证明真实平台能力 |
| 安装与卸载 | wheel 与源码包独立隔离安装、未绑定检查、技能安装/归档及包卸载 | 独立源码包安装用固定构建后端及 `--no-deps`；正常依赖安装由本地与 CI 分别检查 |
| 真实前台闭环 | 安装版原文观察、实际模型版本/摘要回执、原 Codex 入口读回；同编号重复调用无二次发送 | 单次已授权实测，不是持续访问或另一台实体机器实测 |

公共测试和文档使用通用或合成资料。私人实例的线程编号、账户、工具原始回读、配置与运行日志不随包发布。采用范围只覆盖本组件的上述前台路线；Core 治理文件与既有私人配置继续各自管理。

## 自动换窗后续门槛

下列工作仍未验收完成，不能从下载成功或现有契约测试推断通过：

1. 普通 Web GPT 获得官方跨聊天读取、向 Codex 发送和普通 Web 建窗入口。目前受测 Web 客户端没有这些入口；不能用 Work Cloud 聊天替代普通 Web。
2. 官方宿主支持两端身份、项目和代次绑定，并提供可核验的生命周期与未解决投递状态。
3. 用户明确要求换窗时，两端实际模型读取同一交接包，并完成两方向原文投递；随后提交新路由并恢复原任务。
4. 对历史不确定消息逐项对账后才恢复；禁止重发未知消息、改号绕过或清空旧日志。新隔离实例的成功不清算旧实例。
5. 私人正式采用和另一台实体机器验证，分别留下对应版本证据。

缺少入口时保存交接包和恢复点，停止受影响动作。当前实现不增加后台轮询、自动唤醒或私有浏览器接口来填补这些缺口。

## 停止与回退

停止前台调用即可停止新操作；已经提交的消息须继续核对原始回读。技能可通过 `uninstall-skill` 归档到发现路径之外。安装环境和独立本机配置分别处理，保留未解决状态和日志，避免影响其他星枢安装。
