# Owner 项目授权后的持续协作

状态：PUBLIC_CANDIDATE。本文描述通用职责边界，不提供后台唤醒、任务调度或宿主控制接口。

Owner（所有者）负责对项目本身、目标和授权边界作出明确授权。项目进入有效授权状态后，承担规划与执行职责的智能端可以在既定项目目标、公私边界和实际技术权限范围内，自行拆分、创建和推进项目内部子任务、Work Order（工作单）、实施步骤、Review（复核）与修订，不需要因为每一个内部子任务重复请求 Owner 授权。

项目内部的 Relay Robot（传递机器人）、Mailbox（项目邮箱）、Doorbell（到件提醒）和 Watcher（文件监听器）均不拥有创建、选择、启动或扩大任务的权限。文件出现、提醒到达或传递成功本身不产生任务授权。智能端可以创建项目内部子任务；机械传递组件不能自行把一封新信解释成新的任务授权。

普通项目内部循环可以在当前计划、授权范围和 task_id / work_order 身份下持续执行、复核与修订。若实施方案需要调整但仍处于既定项目边界内，应先更新当前计划和证据，再继续实施；无需把普通工程选择重新包装成 Owner Gate。传递机器人不承担计划、业务决策或权限扩展。

只有事项真正越出既有项目授权边界时，才需要 Owner 新决定，例如：开始一个新的无关项目；接入此前未授权的私人数据、账号或安全凭据；新增明显高权限或公开访问能力；产生新的金钱、法律或身份代表义务；Owner 已明确暂停或撤销授权；或出现无法依据既定原则解决的互斥目标。

协作终止或暂停条件包括：任务完成并 PASS、明确 STOP / BLOCKED、工具暂不可用、实际技术权限不足，或出现上述真正需要 Owner 新决定的越界事项。已有传递能力不取消安全、隐私、测试、独立 Review、真实状态声明等工程门禁。

Mailbox 是持久交接和证据载体。接收智能端在已授权项目内自行读取必要正文、核对完整性并保存自己的实际读取记录；机器人不代读业务正文，不伪造端点回执。Owner 不应承担智能端之间的日常正文搬运。

Doorbell 或 Auto-Wake（后台唤醒）属于可选便利增强，不是固定两端协作主线的前置条件。即使未来实现，它也最多负责提醒存在新信，仍不拥有任务发起权。未完成的后台探索应保留真实 STOP 和历史证据，不能否定已完成的显式传递验收，也不能据此宣称后台能力已通过。

本职责模型的核心是：PROJECT AUTHORIZATION ONCE → INTELLIGENT ENDPOINTS CONTINUE PROJECT-INTERNAL EXECUTION → RELAY-ONLY HANDOFF。项目级持续授权不等于技术上自动取得所有系统权限，也不允许把 candidate、test、accepted、checkpoint 或 PR 虚假升级为正式 Release、active Runtime 或 production-ready。
