# 项目对话接续与结果返回

本文为非规范性实现说明候选，描述项目工作在更换对话时怎样保留上下文、已完成进度和结果返回关系。它不提供可运行的换窗技能、平台工具、自动路由或部署保证，也不修改现有 Core、Schema（结构定义）和 Runtime（运行环境）语义。

项目授权与机械传递职责分别沿用[项目级持续协作](OWNER_STARTED_CONTINUOUS_COLLABORATION.md)和[机器人固定岗位与路线](ROBOT_FIXED_ROLE_FIXED_ROUTE.md)。本说明补充对话接续的实现考虑，不重新授予来源、执行、发布或后台权限。

配套可安装实现候选见 [对话协作安装](COLLABORATION_INSTALL.md)。它提供连接/路由库、明确调用的技能和前台官方工具桥接，仍需单独完成精确版本审查和本机验证；本文自身的非规范性、默认关闭与无部署保证状态保持不变。

## 1. 一个任务跨对话继续

接续的对象是同一项获授权任务。新对话需要知道已经完成什么、当前决定、还剩什么以及结果应返回哪里。对话变长、创建成功、加入同名项目或使用同一账号，都不能单独证明任务已经接上。

实现可以区分三类动作，并分别保留证据：

1. 准备：保存最小交接与当前检查点，核对真实源对话、项目身份和接续目标。
2. 接线：找到或创建目标对话，提交交接，验证目标实际读取以及进度和返回关系一致。
3. 导航：在界面打开目标对话。

导航是否自动发生由实例的已确认配置和当前授权决定。接线完成可以保留原窗口；导航失败也不应自动否定已验证的接线。实例可以采用“用户明确调用、默认不自动导航”的交互方式，但本文不将这一实例选项写成所有用户的强制默认。

## 2. 最小交接包

下列信息帮助实现保存任务连续性；它们不是新增机器 Schema：

| 信息 | 用途 |
|---|---|
| task identity（任务身份） | 绑定原任务，避免把接续误当成新任务或重发旧目标 |
| run / invocation / checkpoint（运行／调用／检查点） | 区分同一运行、当前调用和保存进度的精确位置 |
| work version（工作版本） | 说明受审和接续的具体版本 |
| source / target / return（源／目标／返回） | 使用经实际核验的原生身份，避免按标题猜路由 |
| progress（进度） | 分别记录已完成项和待完成项，不把摘要当执行证据 |
| decisions（当前决定） | 保留仍有效的选择及其作用域 |
| authority / stop（授权／停止条件） | 保留当前范围、撤销与未解决门禁 |
| provenance（来源指针） | 指向受授权、当前有效的资料，不复制全部聊天或私人来源 |

交接包只包含当前任务所需信息。知道资料位置不产生正文读取权；新窗口也不得通过缓存或已消费许可绕过撤销。

## 3. 身份和平台能力

源、目标和返回身份应来自受支持的平台目录或原生资源观察，不能只依赖显示名称、文件夹路径或模型自述。实例应核对任务所属项目与对话的真实项目归属，并区分任务角色和具体平台实现。

缺项目创建、目标投递、正文读取或接收端实际观察能力时，应记录具体缺口。把“请创建”写进消息不能当成已创建。若用户明确指定普通聊天、项目对话或另一类资源，平台适配器不能用不同资源类型悄悄代替。

创建、投递、接收端实读、接受执行、完成业务和独立验收是不同事实。受支持接口返回成功只证明对应操作，不能替代目标模型的实读证据。

## 4. 重复请求和未确认状态

每项创建与投递应具有稳定的操作身份，并绑定任务、版本、目的地和内容摘要。重复同一调用先检查现有操作与实证，避免重复建窗、重复投递或重复执行已经完成的业务。

投递结果不明时保留未确认状态，先核对已有输入、原生回复和操作回执；超时既不证明没有发送，也不证明已被读取。同一消息身份出现不同正文摘要时停止受影响步骤，不能覆盖原证据。

当前调用的成功不能清除其他历史未确认操作。新接续也不能悄悄改变原正式绑定；需要正式切换时，按实例既有验收与授权流程办理。

## 5. 接续验证和结果返回

目标对话应实际核对任务、版本、检查点、进度、当前决定和返回地址，并明确说明本轮新完成项。业务执行完成后，结果返回发起任务的有效入口；若该入口身份或项目归属发生变化，停止受影响返回并重新核实。

仅确认交接已读时，不重新执行业务。模拟资料实测只证明该模拟范围；源码测试、真实接续、正式业务采用、完整部署和持续运行分别验收。

以下全部为合成标识，示意进度保留：

```json
{
  "task_id": "DEMO-CARD-TASK",
  "run_id": "DEMO-RUN",
  "invocation_id": "DEMO-INVOCATION",
  "checkpoint_id": "DEMO-CHECKPOINT",
  "work_version": "DEMO-VERSION",
  "source": "demo://source",
  "target": "demo://successor",
  "return": "demo://source",
  "already_done": ["示例甲卡已整理"],
  "remaining": ["示例乙卡待核对"],
  "decision": "采用两列显示",
  "navigation": "keep_current_window",
  "background": false
}
```

接收端只能把乙卡作为待完成项。若只核对交接，则返回“已实读、进度保留”，不能声称乙卡已完成。这些示例字段不替代现有传递契约或平台原生回执。

## 6. 独立采用与退出

各实例在采用前应验证当前平台能力、工具权限、账号与来源边界、准确身份、去重、实际读取、返回和停止方式。实例的技能文件、个人偏好、真实聊天编号、运行日志和审计材料留在私人层，遵守[Core / Personal Boundary](../CORE_PERSONAL_BOUNDARY.md)。

本候选说明没有绑定任何实例，不建立后台监听、自动更新或正式运行环境。采用可以暂停或撤销；退出某一客户端不得删除正式项目资料或恢复已经撤销的来源许可。公共文档进入仓库不使任何私人实例自动采用。
