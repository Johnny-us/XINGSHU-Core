# 固定岗位与固定路线的传递机器人

状态：PUBLIC_CANDIDATE。本文是通用文档候选，不表示公开产品已经发布或具备全部生产能力。

机器人体系采用 Template → Project Instance → Fixed Role / Fixed Route（模板 → 项目实例 → 固定岗位 / 固定路线）。模板定义可复用的空白岗位；项目按需要实例化，并明确唯一实例身份、岗位、路线、权限和对象范围。

Relay Robot（传递机器人）只在项目登记的固定两端之间承担接收、原样保持、送达和机械留痕。它不自动发现端点、选择会话、跨项目兼职、增加第三端或承担另一个岗位。其他项目或路线需要独立实例和相应授权。

Payload（正文）按 opaque data（不透明数据）处理。机器人不得按文字、关键词、业务类型或语义决定是否传递，不改写、概括或执行正文。机械信封可以含项目实例、端点身份、消息标识、字节长度和摘要；这不构成业务内容审批。

可保留的 transport integrity（传输完整性）能力包括固定身份、精确字节与摘要、顺序、去重、机械状态、超时、平台容量限制、快照和恢复。不确定送达时停止，不静默截断或重复发送。一次提交成功、文件上传或消息准备完成不能证明接收端实际收到。

发送智能端负责发送前的业务与授权治理；接收智能端负责收到后的执行权限和实际观察。传递权与执行权分离。机器人不替端点批准任务，也不冒充端点的实际读取回执。

项目内真实验收和项目采用只证明该实例及其已验收路线；不能扩写为任意 AI、任意端点、公共互联网入口或全部用户生产就绪。
