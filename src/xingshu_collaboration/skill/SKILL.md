# 星枢在线对话协作

用户的明确指令优先于本技能。此技能组织已授权的工作，不产生发送其他聊天、访问资料或发布的额外权限。

## 首次使用

1. 确认已安装 `xingshu-collab`（Python 3.11 及以上，macOS/Linux）。缺少时读取仓库 `docs/COLLABORATION_INSTALL.md`。不要更改全局 Codex 配置或安装后台服务。
2. 核对本回合真正提供的 `read_thread`、`send_message_to_thread`、`list_projects`、`list_threads` 工具。记录工具名称作为 inventory JSON；工具名存在不代表账户登录或两端可读。普通 Web 页面不会因为安装本地技能获得这些工具。
3. 用用户选择的独立目录运行 `init`。使用官方工具实际列出项目/聊天并读取两端，核对身份、项目、主机和账户范围。只用唯一聊天编号定位，不按标题猜测。确认用户授权向所选两端发送本任务；已有明确授权不重复索取。
4. 用 `bind` 登记本机两端与授权来源。配置不可覆盖；换绑定前先检查未确认消息。原私人配置、其他机器配置或同名项目不能替代本次绑定。
5. 运行 `doctor --directory … --inventory … --stdio-host`，按下方桥接方法执行实际只读检查。可以读取正在工作的源窗口；检查结果分别列出两端可读和可接收新输入的状态。向忙碌的目标发送时仍停止。工具缺失、登录失败或系统错误时停止受影响动作并保留恢复点。

## 当前在线任务

Codex 主规划和工程推进，Web GPT 按确切版本独立复核。两端的实际角色仍需遵守用户/项目规则，不假定所有实例采用同一治理。

1. 恢复当前授权、版本、已接受决策、未解决问题和证据。给本任务分配稳定的 task_id，每条消息给唯一 message_id。将原文保存为 UTF-8 文件，最大 16384 字节。正文明确列出身份、目的、范围、版本、审查资料的实际地址和 SHA-256。
2. 通过 `send --stdio-host` 投递，桥接到实际官方工具。不使用浏览器私有接口、聊天数据库写入或用户 Cookie。
3. 保存每次原始工具结果和时间。客户端接受、原文回读、模型实读、接受执行、任务结果和独立审查分别记录。`HOST_OBSERVED_INPUT` 仅证明观察到输入；不得写成业务验收通过。
4. 读取目标本任务的实际模型输出，核对精确输入、task_id、版本、资料摘要及原生回合/输出编号。较旧输出、截断或仅 token/布尔值均不算模型实读或独立复核。
5. 处理有依据的 BLOCK，按新版本修订并重验。代码进入公共仓库前去除私人数据，并完成项目要求的独立公私审查。CI 通过不代替独立验收。
6. 返回用户的当前入口。交接期间不得重发旧目标或旧审查请求，也不要自动跳转页面。

## 标准输入桥接

在可保留 stdin 的前台终端启动 CLI（使用 PTY 时程序关闭回显和行长度限制）。CLI 每次输出一行：

```json
{"jsonrpc":"2.0","id":1,"method":"read_thread","params":{"threadId":"…","turnLimit":1,"includeOutputs":false,"maxOutputCharsPerItem":20000},"timeout_ms":30000}
```

只允许执行 `read_thread` 或 `send_message_to_thread`。核对本机登记身份、当前用户授权、method 与 params；将 **params** 原样传给真正的官方工具。`timeout_ms` 是桥接等待上限，不能传入官方工具参数。缺少工具即停止，不能编造结果。

将原始工具返回对象包装为一行后写回同一进程 stdin：

```json
{"jsonrpc":"2.0","id":1,"result":{"content":[{"type":"text","text":"实际工具返回的 JSON"}],"isError":false}}
```

id 必须匹配。保留原始结果，不删改正文、不补写成功标记、不同时写入第二条响应。进程最后输出 result 或 error。调用超时、终止或错误后，先读取 `status`；UNKNOWN/UNCERTAIN 不重复发送，包括更换 message_id 的变相重发。

## 换窗与恢复

仅当用户明确要求新聊天/换窗时，才使用 `list_projects` 与官方 `create_thread` 等支持工具。不同客户端是否支持普通 Web 聊天创建必须分别检查；不能替换为 Work Cloud 聊天来宣称完成。保存原聊天、项目与代次。

换窗前使用公共 `router.continuity` / `router.online_continuity` 契约构造并校验 HandoffPacket：目标、原始入口、有效回执入口、版本、资料摘要、进度、下一步、授权来源和协议摘要。可用 `checkpoint --packet-file` 保存不可变交接包；保存不等于新窗已读取。

使用官方宿主确认没有未解决投递，再建立两端。两端实际模型读取同一交接包，并实际完成两个方向的原文输入观察后，才通过 ContinuityManager 提交新路由。用 TaskCoordinator.resume_adopted 接续业务状态；重复运行返回已有结果。缺任一步保持待接续，不能手改 binding.json 或默认认可未知代次。

## 停止与卸载

停止当前前台调用即停止新操作；已经提交的消息仍须实际核对。程序没有定时器、常驻监听或守护进程。`uninstall-skill` 将本技能移到指定归档目录，保留用户修改和所有本机日志。安装包和本机绑定分别移除，不影响原聊天或其他星枢配置。
